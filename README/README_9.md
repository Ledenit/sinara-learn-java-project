### Что я сделал
Я реализовал демонстрационное Spring-приложение, в котором показаны три вида `EventListener`:
* `CommonEventListener` — обычный, синхронный слушатель
* `AsyncEventListener` — асинхронный слушатель с помощью `@Async`
* `TransactionalEventListener` — слушатель, привязанный к фазе транзакции `AFTER_COMMIT`, чтобы отрабатывать только при успешном коммите

Для каждого слушателя я:
* Создал соответствующий класс события (`CommonEvent`, `AsyncEvent`, `TransactionalEvent`)
* Вызвал публикацию события из сервиса
* Залогировал момент порождения (`publishEvent`) и обработки (`@EventListener` / `@TransactionalEventListener`) с помощью `SLF4J`

Особенность реализации для транзакционного слушателя:
* Первое событие публикуется вне транзакции — сразу же обрабатывается.
* Второе событие публикуется внутри транзакции, которая затем падает (бросается `RuntimeException`), транзакция откатывается, и слушатель его не получает.
